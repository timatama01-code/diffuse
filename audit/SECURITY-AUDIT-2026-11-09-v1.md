# Аудит безопасности Diffuse — v1

Дата создания: 2026-11-09 (+03:00)  
Репозиторий: `https://github.com/MightyCreak/diffuse`  
Commit: `2f52fad93acc8369229ba4443109133c7d904a17` (`main`)  
Объём: приложение, VCS-интеграции, Windows installer, Meson/Flatpak, GitHub Actions, зависимости и вся доступная Git-история.

## Итог

Прямой автоматической отправки сравниваемых документов, телеметрии, встроенного сетевого клиента или известных секретов в коде и Git-истории не обнаружено. Это хороший результат, но он не означает, что весь проект безопасен: подтверждены одна опасная supply-chain цепочка в устаревшей Windows-сборке и несколько рисков средней тяжести в CI, Flatpak-разрешениях и поиске внешних исполняемых файлов.

Главный практический вывод: текущий Python-код можно рассматривать как локальный текстовый инструмент без скрытого слива документов; старый Windows installer из этого дерева собирать и распространять без исправления нельзя.

## Подтверждённые находки

### F-01 — HIGH — непроверяемый исполняемый файл в Windows installer

**Цепочка:**

- `windows-installer/README.txt:27-31` требует скачать `ADD_PATH` по обычному HTTP, без версии, подписи и SHA-256;
- `windows-installer/build.py:278` копирует `add_path.exe` из `ADD_PATH_HOME` без проверки;
- `windows-installer/diffuse.iss:46-50` запускает этот EXE при установке и удалении.

Подмена HTTP-загрузки, сайта или локального `ADD_PATH_HOME` приводит к включению чужого кода в установщик и его последующему выполнению с правами процесса установки. `docs/developers/developers-setup.md:193-196` прямо сообщает, что Windows-порт устарел и не поддерживается, но опасные файлы остаются в `main`.

**Лечение:** удалить `add_path.exe` из цепочки; использовать штатное изменение PATH средствами Inno Setup либо хранить проверяемый исходник и собирать воспроизводимо; закрепить источник, SHA-256/подпись и подписывать конечный installer.

### F-02 — MEDIUM — изменяемые GitHub Actions без SHA

`.github/workflows/ci.yml:19-20,43-44,58-62` использует `actions/checkout@v6`, `actions/setup-python@v6` и `flatpak-builder@v6`. Тег можно переместить; компрометация владельца action даёт выполнение чужого кода в CI.

**Лечение:** закрепить каждый action на полный commit SHA; оставить комментарий с версией; включить Dependabot/Renovate для контролируемых обновлений; задать верхнеуровневое `permissions: contents: read`.

Опора: GitHub Secure Use Reference рекомендует полный SHA как неизменяемую привязку: `https://docs.github.com/en/actions/reference/security/secure-use`.

### F-03 — MEDIUM — привилегированный CI-контейнер по изменяемому тегу

`.github/workflows/ci.yml:55-56` запускает `ghcr.io/flathub-infra/flatpak-github-actions:gnome-49` с `--privileged`, без digest. Компрометация образа или перемещение тега получает максимально широкие возможности внутри GitHub-hosted runner. На pull request также собирается содержимое недоверенной ветки.

**Лечение:** закрепить image digest, проверить необходимость `--privileged`, разделить доверенные release-job и PR-проверку, не выдавать write-права и секреты PR-job.

### F-04 — MEDIUM (hardening) — Flatpak не образует границу безопасности

- `io.github.mightycreak.Diffuse.yml:7` даёт чтение/запись всего домашнего каталога;
- `io.github.mightycreak.Diffuse.yml:12` разрешает D-Bus `org.freedesktop.Flatpak`;
- `src/diffuse/utils.py:200-206` добавляет `flatpak-spawn --host` ко внешним VCS-командам.

При будущей RCE в приложении атакующий сможет читать домашние файлы и выполнять команды вне sandbox. Прямой RCE в текущем аудите не найден; это потеря защитного слоя, а не доказанный текущий слив.

**Лечение:** доступ к файлам через document portal вместо `--filesystem=home`; отказаться от `--host` либо вынести строго ограниченный broker с allowlist абсолютных VCS-бинарников и аргументов.

Опора: документация Flatpak называет доступ к `org.freedesktop.Flatpak` sandbox escape и разрешает его только доверенным приложениям: `https://docs.flatpak.org/en/latest/libflatpak-api-reference.html`.

### F-05 — MEDIUM (условно) — поиск VCS/build-инструментов по имени

- runtime: `src/diffuse/preferences.py:145-170` задаёт `git`, `svn`, `hg`, `bzr` и другие команды короткими именами; `src/diffuse/utils.py:202-206` передаёт их в `Popen`;
- build/install: `windows-installer/build.py:154,188-204,279`, `windows-installer/setup.new.py:268`, `build-aux/meson/postinstall.py:13-19`, `utils/makemanual.py:47-65` аналогично ищут инструменты через окружение.

Подмена возможна при контроле PATH; на Windows дополнительное условие — Diffuse запущен с текущим каталогом, контролируемым атакующим. Переданный в `Popen(..., cwd=repo)` каталог сам по себе поиск EXE на Windows не меняет, поэтому первоначальная оценка HIGH была понижена.

**Лечение:** один раз разрешать инструменты в абсолютные доверенные пути (`shutil.which` до обработки репозитория), проверять путь/владельца/версию, очищать PATH в сборке; не использовать `os.system` для `iscc`.

Опора: Python рекомендует полностью квалифицированный путь: `https://docs.python.org/3/library/subprocess.html`.

### F-06 — LOW — внешние сущности/сеть при генерации документации

`data/usr/share/gnome/help/diffuse/C/diffuse.xml:2-3` содержит внешний HTTP DTD. `utils/makemanual.py:47-65`, `utils/makepdfmanual.sh:3` и `windows-installer/build.py:188-204` вызывают `xsltproc` без `--nonet`; только `utils/makehtmlmanual.sh:3` использует защиту.

Вредоносное изменение XML/XSL в недоверенной ветке может обратиться в сеть build-host или попытаться читать локальные ресурсы во время ручной сборки документации. Этот маршрут не найден в текущих CI-job, поэтому severity LOW.

**Лечение:** везде `xsltproc --nonet`, локальный XML catalog, запрет внешних сущностей и сборка недоверенных PR без секретов.

### F-07 — LOW — зависимости не закреплены и не хэшированы

`requirements.txt:1` и `requirements.dev.txt:2-4` используют диапазоны `~=` без lock-файла и хэшей. Повторная сборка может получить иной пакет или новую транзитивную зависимость.

Проверка минимальных прямых версий (`PyGObject 3.54.0`, `flake8 7.2.0`, `flake8-noqa 1.4.0`, `mypy 1.16.0`) через pip-audit известных CVE не обнаружила. Транзитивный граф полностью доказать нельзя именно из-за отсутствия lock-файла.

**Лечение:** platform-specific lock/constraints с хэшами и автоматическое обновление отдельными PR.

### F-08 — LOW — исчерпание памяти большими входами

`src/diffuse/window.py:397-398` читает файл целиком; `src/diffuse/utils.py:202-211` читает весь stdout VCS целиком. Большой файл или специально сформированный вывод может завершить процесс по памяти.

**Лечение:** лимит размера с предупреждением, потоковое чтение, отмена операции и лимит VCS-output.

### F-09 — LOW/ожидаемое поведение — следование symlink/reparse point

`src/diffuse/window.py:395-400,558-559` читает и перезаписывает путь обычным `open`, следуя symlink/reparse point. Репозиторий может содержать ссылку на внешний файл; чтение произойдёт при открытии, запись — только после явного редактирования/сохранения пользователем. Для текстового редактора это частично ожидаемое поведение, поэтому finding не повышен.

**Лечение:** предупреждать при выходе realpath за корень проекта; перед записью проверять `lstat`/reparse point и запрашивать явное подтверждение.

### F-10 — LOW — postinstall игнорирует сбои

`build-aux/meson/postinstall.py:13-19` использует `subprocess.call` и не проверяет возврат трёх программ. Установка может выглядеть успешной после сбоя или подмены инструмента.

**Лечение:** `subprocess.run([...], check=True)` и абсолютные пути, разрешённые Meson.

## Проверка слива информации

Подтверждено:

- импортов и вызовов `requests`, `socket`, `urlopen` для отправки документов нет;
- скрытой телеметрии и автообновления нет;
- сравниваемые файлы не загружаются наружу;
- Help по явному действию пользователя открывает `https://mightycreak.github.io/diffuse/manual.html` и добавляет только код языка (`src/diffuse/window.py:1703-1710`); браузер передаст обычные сетевые метаданные — IP, User-Agent, язык запроса, но не содержимое документов;
- VCS-интеграции могут штатно обращаться к удалённому SVN/CVS/Git-репозиторию по команде пользователя; это функциональность VCS, не скрытый канал;
- Flatpak manifest не выдаёт сетевой socket, однако `flatpak-spawn --host` ослабляет это ограничение, см. F-04.
